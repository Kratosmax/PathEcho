# 启动自动检查更新：复现与本地修复

日期：2026-11-11。基线 main 2a3d2dd / 正式 v0.8.0，修改均未提交或发布。用户现场的当前版本、手动检查结果和启动方式尚未确认，不能只凭代码缺陷宣布已定位其现场根因。

## 已确认缺陷

App 在 --background 或 StartMinimized 条件下创建主窗口但不调用 Show。后台检查得到 Available 后，UpdateWindow 构造函数立即设置 Owner=主窗口；WPF 拒绝从未显示过的 Owner。

真实WPF隔离复现：ownerEverShown=false 时抛 InvalidOperationException（无法将Owner属性设置为之前未显示的Window）；ownerEverShown=true 构造正常。结果在 temp/startup-update-probe/baseline.json。

原代码捕获异常后只调用受Debug开关控制的AppLogger.Error和隐藏状态栏，因此用户可能既看不到更新也看不到错误。当前服务已经是最新版本时原设计同样不弹窗，这属于正常静默结果；二次启动若已有托盘进程，也不会走一次全新的初始化检查。两种情况必须与缺陷区分。

## 修复

- 非preview首次启动统一进入策略，由策略检查保存后的CheckForUpdates；禁用时不发请求，保留明确Skipped记录。
- 只有得到Available时才显示/恢复主窗口，再创建有合法Owner的更新对话框；Latest/ManualOnly/失败保持后台，不无谓弹窗。
- 更新窗口接收已验证结果并直接展示，不重新获取第二次清单，避免二次网络错误覆盖已发现版本。
- 关闭窗口/退出取消延迟和请求；单飞防止重复启动检查；45秒取消期限可反馈检查超时。网络客户端需要遵守取消，未将此表述为所有同步OS I/O可强制中断。
- 设置页显示本次自动检查状态；默认诊断记录start/结果/失败类型和错误码，不依赖Debug。
- 启动/手动入口共享活动更新窗口；窗口已显示时仅激活现有窗口，不再叠加另一更新窗口并竞争同一下载文件。已补共享窗口回归。
